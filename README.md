# 影作 · 一幕团圆

据传统故事《劈山救母》原创交互改编的皮影戏与数字展馆，参加2026年零杯零组，主题为“匠心传成，非遗焕新”。程序、美术与中文配音使用AI辅助；数字设计和合成配音不作为传统皮影实物、演员录音或地方唱腔的记录。

本文按2026-10-27主线实现整理。当前默认剧本为 **v5**，四次累计选择和分角色本地配音已接入，旧v1—v4按原版恢复与重演。T37已完成；T38制作、接线和功能核验已交付，仍待人耳听感验收。全站尚未完成正式素材审看、实体设备验收和最终交付，实际状态以[任务账本](docs/tasks.json)、[当前交接](docs/STATE.md)和对应验收证据为准。

## 作品与体验

推荐顺序：故事缘起 → 制偶 → 调灯 → 练习 → 正式演出 → 留影成果 → 展馆。各页允许直接进入，展馆无需先通关。

- **制偶与操演**：为沉香选择整套或衣身、袖、下摆配色，保留原画刻纹；直接拖动四肢、牵动身杆或用舞台方向键移身，另有按钮和关节滑块。制偶页试提不改变练习台保存的姿态。
- **灯影与空间**：调灯页默认使用固定影偶、可直接拖灯的三维工坊，观察彩色幕影；可切回完整二维。普通舞台可主动展开空间，观察剧情景片、人物和幕前幕后。
- **故事与成果**：每段先对白，再交给观众操偶，达标后收杆定场。可协助、跳过普通片段或重看，选择必须亲自确认。实际终章后可下载1600×1200 PNG、本场JSON，并按本场编排只读重演。
- **知识展馆**：五区七件公开展签、17个配图展示位，其中12张是不同的外部实物或工艺照片。图文与来源可独立阅读，照片支持放大、懒加载和失败重试。
- **引导与呈现**：各工序有可跳过的隔离试练，结束后还原作品与页面状态。首页采用莲灯画、单次柔幕和本地书法题字；正文、剧情、导航与控件使用常规楷体，装饰动效服从开关及减少动态设置。

只有沉香可定制和操控，母亲、二郎神使用脚本动作，同屏最多两角色。Canvas 2D完整覆盖故事与展馆，Three.js增强空间与材料。人物与灯影是本作数字艺术表达，投影为交互近似，不宣称精确光学仿真。

## v5故事、自动播放与声音

v5共38节点，每条路线经过23节点。观众依次决定途中愿望、承山约定、山前先后和最后暂缓／兑现，16种组合确定性派生归家、守灯、同行、开放相守、化山五种终章，最后不再直接选取五个结局。选择回顾和成果规则见[v5契约](docs/contracts/story-v5.md)。已有场次不迁移，体验v5需在制偶页明确归档重开。

T40修复制偶入口曾误用v4的问题：首页、制偶页“用这身行装开演／采用默认影偶开演”以及归档重开共用当前剧本版本，完整与导览均使用v5。修复前已误建的v4场次仍按原版保留，剧场会显示没有新增配音的说明及制偶入口；需要中文配音时，可先导出作品，再明确归档重开，无需清空本机历史。

正式剧场在页面可见、有焦点且资源与存储就绪后，首次进入、刷新、返回和正常切章会从当前稳定短片段起点自动开演。无场次时仍须明确开场，行装、选择和操偶仍由观众完成。同页主动暂停、重开、切换节奏、失焦、长停顿及资源／保存失败会撤销播放意图，回焦或失败重试不自行复活；再次进入可见剧场按新入场请求处理。播放票据和瞬时时间不写入存档，见[自动开演契约](docs/contracts/automatic-performance-v2.md)。独立练习和成果重演仍默认暂停。

v5使用354条预生成的本地原始MP3，覆盖完整／导览、合法选择派生对白、五终章和成果重演：

| 角色 | 声线 |
| --- | --- |
| 旁白 | Yunyang |
| 沉香 | Yunxia |
| 母亲 | Xiaoxiao |
| 二郎神 | Yunjian |

中文配音、戏曲音乐和合成舞台音效默认开启，意图开关相互独立，在当前页面会话内保留，刷新回到默认。浏览器可能要求点击或按键解锁声音；配音受阻时有显式重试入口，画面与完整字幕仍可继续。实际人声播放时伴奏降至原音量25%，等待、结束或暂停后恢复；v5谢幕先说完对白，再播放原40秒唱段。旧v1—v4不请求新配音，也不采用新配音时间编排。

配音按实测时长编排，完成门槛、字幕、定位、导演和重演使用同一时间适配，媒体回调不推进剧情。暂停、失焦、教学、保存阻塞和离页均清理旧播放。音乐采用京剧《贵妃醉酒》的京胡器乐与宋若萱唱段节选，并非本剧原创唱腔，来源、CC BY 4.0署名及处理说明见[素材致谢](credits.html)。

完整模式对白／定场编排约22.54—22.72分钟，导览约8.10—8.17分钟，均含40秒谢幕唱段，不含可选行装台词和手动操偶停留。这是编排求和。现有自然时钟导览记录为572.451秒（约9分32秒），使用减少动态、辅助操偶，并含一次长停顿保护后的显式继续；完整模式自然全长、人耳听感和实体设备混音尚未验收。不能沿用旧版“完整6—8分钟、导览3分钟”的说法，详见[T38验收](docs/acceptance/t38.md)。

## 本地启动与生产预览

仓库已改名为[herspacefly/YingZuo-ZeroCup](https://github.com/herspacefly/YingZuo-ZeroCup)，公开网站为 <https://herspacefly.github.io/YingZuo-ZeroCup/>。本地目录仍可保留原来的`ZeroCup`名称，不需要重新克隆或移动工程。

已有检出只需将远程与跟踪关系更新一次：

```powershell
git remote set-url origin git@github.com:herspacefly/YingZuo-ZeroCup.git
git branch --set-upstream-to=origin/main main
```

GitHub的Settings → Pages → Build and deployment → Source选择 **GitHub Actions**。仓库内`.github/workflows/pages.yml`会在每次main普通push后安装、检查、构建并发布`dist/`，也可从Actions手动运行；不要再发布源码根目录或选择Jekyll模板。日常按原习惯修改、提交、`git push`即可；公开网站在工作流部署成功后更新，进度见[部署工作流](https://github.com/herspacefly/YingZuo-ZeroCup/actions/workflows/pages.yml)。

日常修改后，在本项目目录、`main` 分支执行：

```powershell
git status
npm test
npm run build
git add -u
git commit -m "描述本次修改"
git push origin main
```

`git add -u`暂存已经跟踪的文件改动；如有需要发布的新增文件，先用`git add 文件路径`添加。推送后到上面的Actions页面查看最新运行，等构建与部署均成功，再刷新公开网站；不用手动上传`dist/`。

Vite使用相对base，展馆照片也按部署base解析，同一生产包可用于根路径和项目子目录。公开域名与localhost的浏览器存储互不共享，需要接续本地作品时先导出JSON，再在公开网站导入；服务器不会上传或同步本机IndexedDB。

T39已实测普通push触发构建部署，公开首页HTTP200，根／子目录宽窄12项及公开站点宽窄6项功能检查通过，详见[部署验收](docs/acceptance/t39.md)。公网冷加载存在等待波动，功能检查与15秒性能目标、真实设备及听感验收分别记录。

使用Node.js **24.x**与npm **12.x**，最近验收环境为Node v24.18.1、npm12.0.2，依赖以`package-lock.json`固定。

```powershell
npm ci
npm run dev
```

开发服务默认 <http://127.0.0.1:5173/>。构建与生产预览：

```powershell
npm run build
npm run preview
```

生产服务默认 <http://127.0.0.1:4173/>，产物位于`dist/`。必须使用HTTP静态服务器，不能直接双击HTML运行模块；保留整个构建目录的资源相对结构。配音地址支持子目录部署，已有`/nested/`原生媒体验证。

**运行网站不需要在线语音服务、Python、FFmpeg、API密钥、CDN或远程字体。** 提交目录已包含配音、图像、音乐和字体。重新制作配音才需要隔离Python环境、`edge-tts==7.3.1`、FFmpeg／ffprobe及服务网络，制作与续跑步骤见[配音验收维护说明](docs/acceptance/t38.md)。
