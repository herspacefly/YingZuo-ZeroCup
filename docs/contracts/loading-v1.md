# 素材加载验收合同 v1

2026-10-20，作者明确允许较大的图片和音频，只要大概15秒内能够加载出来，不必强行压缩或删减。现行数值由 `scripts/art/loading-policy.mjs` 统一提供；原图片/字体2MiB是历史参考，不再单独阻塞验收。完整素材、像素、来源和许可校验继续保留。

## 实际可用时间

- 图片：从用户实际打开序幕，到完整Canvas就绪、存档saved且播放按钮可用；目标≤15000ms。首页可操作时间另记，仍保留本机2秒/限网5秒目标。
- 音乐：从实际启声操作（首页器乐）或已准备且暂停的谢幕实际播放操作，到目标原生媒体未暂停、readyState≥2且currentTime>0.05；目标≤15000ms。这表示已开始播放，不表示整曲下载完成、扬声器听感或所有设备通过。
- 计时使用原生时钟和实际资源。报告分别记录本机、5Mbps/150ms、冷context/禁HTTP缓存的桌面及模拟窄屏，不把模拟视口当实体手机。不清OS文件缓存，不限制CPU。

15秒是验收目标，不是产品超时强制中断，也不新增虚假加载百分比。实际加载或解码失败仍反馈真实错误并支持重试；离页取消并释放。音乐默认关闭，暂停时开启偏好可以不创建媒体对象，不能用enabled状态代替真实起播。

## 独立约束与证据

首页、入口gzip JS≤200KiB、运行帧率和draw calls继续独立判定；剧情时钟断档、团圆静候及P1十五秒录制均不受本合同改变。当前无损传输与PNG兼容路径保留，不为历史体积门槛删图、降低色彩或省略音频。

`measure-startup.mjs`判定首页及图片实际就绪，字节统计仅列历史参考；`measure-music-load.mjs`检查原生音乐就绪并记录buffered范围及HTTP媒体响应。历史JSON及其当时的2MiB失败保留，新口径使用独立的`t10-loading-*`与`t10-music-readiness.json`，不改写过去。
