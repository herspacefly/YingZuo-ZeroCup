# T10 审看材料与内容复核实施计划

**Goal:** 将当前127项审看对象整理为可浏览、可查来源的具体材料，修正实际查出的内容问题，并形成后续验收缺口映射。

**Architecture:** 独立的只读HTML快照由现有清单、剧本、展签、事实、来源、声音配方和审看账本生成；不进入产品路由，不写IndexedDB或审看账本。内容摘要和现有审看记录逐项并列，变更或待审如实显示。当前参考分件美术、存档和时钟保持原行为。

**Tech Stack:** Node.js 24、现有review-gate、普通HTML/CSS与少量无依赖筛选脚本；本机浏览器验证。

1. root新增scripts/build-review-packet.mjs，生成docs/reviews/t10-review.html。按三角色分件、场景/附件/纹样、18剧情、八展品、20事实及声音分组；80张PNG可放大，原画/实际舞台辅助审看，来源含访问边界。复用reviewSubjects摘要，不另建批准标准。
2. 页面仅支持搜索、分组浏览、展开与打印，没有一键批准、许可推断或后台写入。文件和本地开发服务均能打开；所有文本转义、外链仅HTTP(S)、资源路径限制在仓库。
3. 生成器提供--check比较当前内容与产物，内容或审看状态改变后旧材料报stale，不静默覆盖。输出须覆盖全部127个唯一ID，重复生成字节一致。
4. 文化只读执行者按官方来源核对表述和可访问边界；root据可核查证据做必要修正，并同步来源、叙事和审看摘要。另一只读执行者映射现有SAVE/环境/性能证据与缺口，提供后续实测步骤，不标T11/T13已通过。
5. 实际打开宽窄屏审看页，核对图片、全部条目、搜索与键盘、外链、无横向溢出、无业务存储写入。脚本check及资产/内容/状态检查按变化执行；纯审看样式不堆镜像单元测试。必要的产品内容变化只跑受影响检查。
6. 更新任务/交接/实际验证，提交仅本任务文件，保留用户DOCX/PPTX暂存原状，清理临时输出。T10审看仍由作者实际决定，实体环境和真人体验按原门槛保留待测。

验收准备补充：docs/acceptance/t11-readiness.md记录SAVE、设备和真人/性能缺口及可填写模板；scripts/inspect-build-budget.mjs只统计当前dist现代入口及显式modulepreload的gzip JS，输出逐文件SHA和范围，不称冷启动/网络/fps/实体设备通过。T11/T13不提前改状态。
