# 冷启动、首段资源与环境预检计划

**Goal:** 按START_HERE的下一步，完成当前机器可执行的生产包性能测量与额外尺寸/断外网准备，实际失败则修复，持续推进到需要外部输入或真实设备的边界。

**Architecture:** 独立Node/Playwright测量脚本启动Vite生产预览，以真实时钟观察已可操作且绘制的首页与序幕。每次新context、缓存禁用，无存档、音乐默认关闭、三维默认不加载；本机与CDP 5Mbps/150ms分别至少三次，1440×900与模拟手机390×844分别记录。测量工具不进入生产代码，不伪造时间或交互完成。

**Tech Stack:** 当前Node24/npm、Vite preview、Playwright Chromium/CDP、真实IndexedDB与产品页面。

## 顺序与所有权

1. codex-root核对dist/index及静态入口指纹，创建scripts/measure-startup.mjs，收集首页首次可操作、实际点击后序幕就绪、PNG/字体体积、失败请求和设备/网络/缓存条件；保存全部样本与最差值，不只报平均数。首页目标本机≤2秒/5Mbps+150ms≤5秒，首段必要图片与字体≤2MiB。
2. 若失败，定位网络/解码/绘制/交互边界并按测量证据做最小优化；不擅自降低正式图片质量或改故事/存档契约。必要时按既有Code/brainstorming流程记录实现方案，定向验证后复测。
3. 独立只读initial_resource_audit只查实际所需资源/可疑预载；environment_preflight_audit只查现有覆盖与最小验证方案，不运行浏览器/基准，避免干扰本机性能测量。所有代码由root串行修改。
4. 完成测量后，补1920×1080与1024×768的两模式/两路径与相关页面，实际阻断非本地网络但保留本地资源服务，验证故事/展馆/结果/下载/保存。复用已有真实操作与明确协助，不直接篡改完成位；不把受控导演时钟称真实体验时长。
5. 更新证据/状态/账本，必要的小阶段及时提交，再继续下一项可执行准备；不因一个检查通过结束。正式审看、实体浏览器/设备或至少3位外部体验等真实外部条件须明确交接；测得的技术目标失败另列，不改称通过或只剩外部阻塞。

## 边界

- 当前仍在T10审看期间准备；T11/T13/T14不跳依赖，不提前标done；P1仍未启用。
- 冷启动本机测量不证明实体手机、远程部署、真实FPS/听感或全程时长。
- 用户已有START_HERE.md三处未提交编辑与两份暂存DOCX/PPTX保留；不把其编辑混入本任务提交，不读取二进制内容。
- package/锁、ProjectV1与唯一导演时钟架构保留。原生观测发现首次RAF早于click时间会误暂停，因此允许一次首帧修复；不移动播放基准，后续倒退、非有限与>250ms仍暂停。清理本轮临时产物，必要测量记录保留。

## 实际结果

基线12次已完成：首页均满足2秒/5秒，但首段55张PNG为4,289,566bytes，真实超出2MiB；限网序幕点击到就绪中位数约7.7—7.9秒。完整样本见startup-baseline.json。

已实施无损优化：81张PNG原始及浏览器RGBA完全一致地重编码；三图alpha独立校验一致，生产只传color+regions；61张较小WebP绑定canonical SHA，经非预乘ImageBitmap→原尺寸Canvas→本地data PNG→原生Image，消除不同源类型的缩放/上传差异。半透明能力探针失败或legacy用canonical PNG；Three消费者保持原生Image。正式源像素、绑定几何、ProjectV1不变。现代三纹样开场静态39资源均小于2MiB，wave仅余512bytes；PNG兼容约3.16MB仍失败。

预检另补两桌面尺寸、减少动态且禁WebGL的宽窄屏，每种环境完整/导览×两路共16条流程；保留断外网、真实媒体、手动最后伸手、8展品、PNG/JSON与恢复证据。受控剧情时间不算实际演出时长，模拟手机鼠标拖动不算真实触屏。原生时钟12次点击复现3次首帧误暂停，修复后再次出现3次早帧且0误暂停。软件GPU采样的绘制调用预算通过，原生回调率仍未达桌面目标。
